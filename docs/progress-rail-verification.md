## 样本与实际测试

样本是项目自带的确定性合成双峰验证谱，来自 `src/demo.js`。它只用于检查进度状态和界面行为，不作为实测能谱证据。测试日期：2026-09-19；环境：本地 `http://127.0.0.1:4173/`，Codex 内置浏览器。

| 场景 | 操作与预期 | 实际结果 |
| --- | --- | --- |
| 桌面固定布局 | 1280×720 打开并向下滚动；进度栏位置不变、不覆盖主区 | 进度栏 `top=112px`，滚动约 605px 后仍为 112px；右栏与主区间距约 17px |
| 无数据初态 | 打开页面；四步呈等待/可选状态 | 符合预期，进度栏可见 |
| 正常流程 | 载入合成谱、寻峰、标定、匹配 | 窄屏入口依次显示第二、第三、第四阶段及第四阶段完成；四步文案同步 |
| 输入变更 | 完成后修改显著性阈值 | 寻峰结果失效，进度回到第二阶段 |
| 窄屏 | 390×844 和 320×640 打开入口、关闭或按 Esc | 入口固定在语言按钮上方；面板可展开与关闭；320px 视口内面板宽 296px |
| 语言 | 切换至英语 | 进度入口、四步状态及关闭按钮均切换英语 |
| 尺寸变化 | 从桌面切到窄屏，再回桌面；窄屏展开后切回桌面并再次缩窄 | 面板可访问状态与入口显隐随视口更新；再次缩窄时面板默认收起 |

初次浏览器测试发现 `src/app.js` 在元素查询函数初始化前绑定进度按钮，页面报 `ReferenceError`。已调整初始化顺序，重载后重新完成上述交互测试。最终执行 `node scripts/check.mjs`：15 个模块语法检查及 57 项自动测试通过；`git diff --check` 无内容错误。自动测试不覆盖全部视觉布局，以上浏览器操作用于补足该部分验证。

运行方式：在项目根目录执行 `npm start`，访问 `http://127.0.0.1:4173/`。修改进度布局或状态逻辑后，应重新检查桌面滚动、窄屏展开、语言切换和输入失效回退。
